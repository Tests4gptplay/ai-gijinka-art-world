# 路线 E｜受控 AI 图像/视频素材 + 可重复合成

**仅作为候选素材生产轨**：ComfyUI 工作流 / 具备明确许可的视频模型（如 Wan2.2）→ 带可追溯来源的短背景/插画/镜头 → A/B/C/D 时间轴内合成。

## 解决什么、不解决什么

可能解决：复杂具象背景、华丽材质、烟雾流体、环境镜头、图片补全、角色插图试样、部分高质短镜头。在用户希望“画面不是几根线”时可迅速提高画面丰富度。

**不保证**：连贯 3.5 分钟视频、同一 GPT 白龙娘的角/膜翼/鳞尾在每个镜头都一致、精确歌词、眼神/动作连续性、免费低显存批量渲染、原作者风格的授权合规。

官方 ComfyUI 支持图像生成/编辑、视频生成、参考图条件、工作流 JSON 与种子保存；这些能力**不是质量认证**。Wan2.2 官方 repo 介绍了 720p TI2V-5B 等模型，其例子要求约 24GB VRAM 或更高；另一些大模型配置约 80GB VRAM。**没有核验用户主机的 GPU/显存，不宣称可在 CAH Runner 运行**。

## 建议限定的使用方式

1. **先做原图/角色身份锚点**：明确人物来源和改编条件；角色资产必须锁定外形：GPT 白龙角、浅紫翼、白鳞尾、白紫礼裙。
2. **单段生成不是最终时间轴**：按 shot-id / seed / model / weights hash / reference hash / render configuration 提供候选，注明生成模型。
3. **短镜头先对照**：每个生成镜头都要看原始连续视频，特别检查肢体/龙角/尾巴消失、额外肢体、服装漂移、背景结构突变。
4. **字幕/UI 后合成**：原图里出现的文字容易失真；统一把准确歌词、IDE 字符、状态图放到 A/B 的确定性矢量/DOM 叠层。
5. **必要时回退**：如果跨镜头角色身份不能稳定、重采样成本过高或许可不清，采用角色分层图 + 骨骼/关键帧动画，不继续赌生成。
6. **音频保持原始合法路径**：未经许可的音乐不推给外部 API，公开 Git 不放歌曲；宣传片中的音乐署名与非官方声明按实际原作者要求处理。

## 使用的权利与部署边界

- ComfyUI **应用仓库本身是 GPL-3.0**；模型权重、不同节点、外部服务还有**各自**的许可，不能用 ComfyUI 的许可证替代整套管线权利审核。
- Wan2.2 官方 README 描述其模型受 Apache-2.0，具体权重/附加限制应对当前模型版本逐一复核。
- 下载模型、安装大型创作工具、购买在线生成额度或发送受保护的音乐/人物资产到外部服务之前，必须按实际用户授权执行；本研究不启动相关依赖。
- 对“完全由编程逐帧制作、没有图片/视频生成模型”的创作申报，**只有实际管线确实未使用 E 才能作此声明**，不能因为最终画面由 FFmpeg 编码就伪称没有生成模型。

## 是否成为主线？

**暂不建议 E 单独担任全片主线。** 它的主要价值是有控制的资产与部分镜头质量补充；稳定字幕、时间轴、形象连续性仍由 A/B/C/D 的受控系统承担。
