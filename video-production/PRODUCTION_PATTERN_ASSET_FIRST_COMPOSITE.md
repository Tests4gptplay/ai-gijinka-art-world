# 高表现力资产先行 + 统一时间轴合成：可复用制作模式

> **研究规范提案 / 未实施**。灵感源于 [《千本樱》多工具 MV 案例](CASE_STUDY_SENBONZAKURA_OPUS_20261017.md)。目标是提高 AI 主导视频的可维护性、可读性和视觉上限，**不是固定每个作品都必须用 Blender 或 ComfyUI**。

## 主张

**“创作自由”应包括允许模型自主选择合适的专业资产和镜头媒介，而不是被当前最容易写的绘图循环绑住。**

把创作划为五个可验收但松耦合的阶段：

```text
音乐/剧本/世界观 → 美术圣经 + 分镜 + shot manifest
          │
          ├─ 场景 / 环境 ──→ Blender、Godot、原创建模 / 拍摄
          ├─ 角色 / 道具 ──→ 合规插画、分层、ComfyUI + 修图
          ├─ UI / 字幕 ────→ CSS/SVG/矢量设计/字体
          └─ 特殊效果 ────→ Shader/粒子/多层合成
                          │
                 统一资产索引 + 风格检查
                          │
                Remotion / Motion Canvas
                   全局 n/fps 时间轴
                          │
                      MP4/音频
                          │
          连续运动 + 音画 + 角色 + 美学审片
```

一个镜头可自由采用完全程序化表现、分层人物画、Blender 3D、特效、局部 AI 图像生成等。**统一的是帧时钟、资产接口和验收，而不是镜头内容的生成机制。**

## 1. 概念到摄影构图：先锁定可见事件

不要仅写“记忆破碎 / 意识觉醒”。写成**观众能看到的动作与画面关系**，比如主体从哪个空间来、如何受阻、做出何种选择、变化后留下什么结构。给出镜头景别、焦点、镜头转场、可读文字的安全区、每段音乐的情绪变化。

美学基线：
- **角色主视觉先可辨**：AI 娘须依据 [角色图鉴](../CHARACTER_ATLAS.md)定位，GPT 是白龙娘、Qwen 持扇、DeepSeek 鲸尾女仆等；允许自有二创设计但必须注明来源和宇宙层级。
- **风格在分镜阶段解决**：指定画线、纹理、材质、光源、阴影、色调和文字系统；生成的角色图与 3D 场景不能互相“贴错画风”。
- **至少两种不同的真实动态原型**才能决定要不要整曲投入；失败可以否决工具而不是勉强把粗糙元素摆动拼满视频。

## 2. 按资产类型分包，优先复用已有能力

| 资产类别 | 可选制作方式 | 实际 QA |
|---|---|---|
| 历史街景 / 室内 / 复杂物理空间 | Blender、Godot、合规现成模型/原创建模 | 三视图、材质/灯光、机位、真实高分辨率镜头可读性 |
| AI 娘 / 主角 / 表情 | 可用的高质量分层资产；ComfyUI/Anima 等参考生成；GPT Image 精修 | 主角脸型、角翼尾、发丝/衣边 alpha、姿态、手指、跨镜头一致性 |
| 字体 / 歌词 / 终端 UI | HTML/CSS/SVG、PixiJS、Motion Canvas | 中文字体与字距、可读性、动态系统真实性、安全区 |
| 镜头特效 | Three.js/GLSL、Blender 合成器、后期滤镜 | 有表现目的，不遮角色眼睛/歌词；不同场景的层级和对比 |
| 音频与时间轴 | 本地合法音频、Remotion/等价帧编排、FFmpeg | 确切 cue / frame/PTS、音频轨完整、播放器试听 |

**ComfyUI Anima 是模型权重与工作流的一种选择，不是所有创作的指定画风。** 所需算力、模型许可、输入数据传输范围必须单独确认。

## 3. 给模型可操作的能力目录，而不是一条只会画线的执行入口

未来准备制作系统时可以给 Agent 一份经过授权和物理可用性验证的 capability 清单：

`capability_id, type, environment, read/write boundary, preview command, render command, version, input/output contract, license_status, permission_status, failure_fallback`

示例：`blender-scene-author` 用于镜头/布光/渲染，`comfyui-character-art` 用于候选角色图，`image-retouch` 用于边缘/风格修复，`remotion-timeline` 统一帧/合成。这些都是**虚构的能力名称示例，不表示本仓有这些已注册的 Tool 或正在运行的服务**。

**安装/外部调用**：无论原作者评论如何，不能把“自动下载所有工具”作为默认许可。大型专业软件、模型权重、第三方插件、外部账户/API/费用、发送私有素材，都应依具体环境的授权与安全界限处理。

## 4. 固定素材传递契约，但允许每镜头选择媒介

最低要求见 [asset-workflow-contract.example.json](asset-workflow-contract.example.json)（仅设计示例）。建议每份资产至少有：

- 作品/镜头 ID、作者/创作方式、形象参考与授权、原始生成/编辑的模型版本和 seed（适用时）。
- 源文件 SHA、内部存放路径、分辨率、像素比/alpha/premultiply、色彩空间、FPS 或帧窗口、面向镜头的安全边界。
- 3D 场景资产的摄像机、视角/焦距与灯光预览；人物的分层、锚点、透视变化范围；视频片段的时长/音轨/PTS。
- 一个供统一合成调用的 `shot` 入口。不要让时间轴层通过复制一整段作者口头描述重新生成人物与场景。
- 对外展示的技术/AI 参与声明：图像是生成/精修/手绘/程序生成哪一种，不能由导出方式倒推。

这里的“可重复”主要是工程追溯、版本输入与镜头级复现，**不是**跨驱动/生成权重都能二进制逐像素一致的承诺。

## 5. 独立美学闸门比自动技术绿灯优先

在任何完整音乐渲染前，必须对最终编码的 8–12 秒多镜头短样进行**可播放、可见、可听（有条件时）的独立审片**。对照 [QUALITY_GATE.md](QUALITY_GATE.md)：角色是否真正融入背景、二维人物是否像贴纸漂浮、阴影透视是否一致、画面能否让观众感受叙事而不是仅感受滤镜、转场是否与音乐关联、歌词是否阅读清楚。

最常见的“看起来更好但依旧不过关”的问题：
- 高精人物 PNG 靠 2D 位移循环漂浮，没有角色表演；
- Blender 3D 与二次元立绘光向、景深和镜头语言不协调；
- 不同 ComfyUI 图之间脸、衣服、龙角尾巴发生变化；
- Remotion 只有卡片飞入飞出，本质仍是 PPT；
- 高级 shader 粒子很多，但世界/选择/情绪未被观众感知。

## 6. 对本仓已有路线的影响

这是现有 **[A 浏览器合成](PATH_A_WEB_CINEMATIC.md) + [C Blender](PATH_C_BLENDER.md) + [E 美术素材](PATH_E_GENERATIVE_HYBRID.md)** 之间的生产架构参考；**并不替代 B Motion Canvas、D Godot、纯程序化作画**。后续试验应根据作品需要决定工具数量，工具多并不等于更有艺术感。

本轮不提交软件依赖、生成图、镜头工程、声音、私有密钥，也**不会干预进行中的 CAH 制作任务**。
