# 高品质程序化 MV：可操作的美学验收协议（拟议版）

**核心：先问“画面是否打动人、能否准确传达自我构思”，再问“程序有无错误”。** 仅固定渲染器不可能保证美学质量。协议适用于 A–E 任意一条路线，首先需要真实的连续编码视频；评审者可以是独立模型和人类，但不能谎称已听过声音或看到未加载的素材。

## 阶段 0：概念 → 可看画面的设计契约

写下这一段音乐的**可视意图**：情绪目标、主镜头、空间/版式/角色主次、动态事件、颜色节奏、代表性构图、技术选择理由。将它拆成 **观察者能从画面识别的事件**，而不止“观察者诞生/冲突加剧”文字抽象。

## 阶段 1：15 秒以下真实动态样片（不得跳过）

- 相同音乐/合成节拍、时间码、节奏节点；同一分辨率/编码/FPS。
- 至少 **两种不同演出方案**（不是简单调亮/改几何曲率），优先 A 与 B；必要时追加 C/D/E。
- 每版包含开场/推进/高潮/收束（在 8–12 秒内至少 3 个表达有差异的动态事件）、稳定色彩层级与清晰主视觉。
- 结果是真实编码视频以及按时间抽出的帧，不能仅有 HTML 截图、真实素材预览 GIF、华丽的 AI 想象示意图或者源码日志。
- 未通过才修改镜头设计、层级、材质、叙事语法甚至工具路线，不要只无限修细线 alpha 亮度。

## 阶段 2：独立艺术判定（须有“可以拒绝”的权力）

独立审片者必须看实际运动、能看视频音频就**确实听**，且尽可能**盲看**方案名称，以降低“用了高级技术所以一定好”的偏见。

必须写出以下问题的逐项结论，全部要有实际画面/时码举证：

| 门槛 | 问题 | 失败典型 |
|---|---|---|
| **表达转译** | 不解释设计文案，能否感知形象在做什么？ | 说明写“压迫”，只看到圆圈放大 |
| **空间与层级** | 主体/背景/景深/遮挡/明暗组织是否有层次？ | 全片黑底、两笔暗线反复摆 |
| **演出与运动** | 是否因音乐变化而有动作、镜头与事件？ | 30 秒近似静止或匀速摇摆 |
| **角色连续性** | 人物的头饰/种族、脸、服装、肢体是否一致？ | GPT 龙角/尾巴消失或误成 Qwen |
| **审美完整性** | 色彩、字体、界面、材质、转场是否统一而有变化？ | 每段看似不同，却只改颜色 |
| **可读和舒适** | 中英歌词、UI、关键情绪点是否清楚？ | 主体遮歌词、闪烁、暗得无法看清 |
| **差异化** | 是否明显优于低成本基础几何绘制基线？ | GLSL 只把原本的线变成发光线 |

评价维度可以用 1–5 参考档次做记录，但**数值绝不是客观美学真理**。采用**关键门槛 veto**：如果观众看不出场景意义/主要角色身份/音乐节奏/连续运动，即便所有技术指标绿，也先标 `ART_REWORK`；艺术是否满意由真实审片理由支撑，**不是因为任何人事先质疑就默认不合格**。

## 阶段 3：工程和渲染验收

- `n/fps` 全局时间轴、镜头边界、统一字幕 cue、安全区域，帧数、PTS、音轨时长和原曲不变性；
- 记录工具版本、随机种子、GPU/浏览器后端、素材/脚本 SHA、实际耗时、缓存/温度影响（不虚构速度指标）；
- 最终实机输出 MP4 + `ffprobe` + 实际全片/整段解码 + 端到端的首中尾音轨验证；
- 跨 scene seek 重新渲染同一帧，需要确定性结果；涉及 GPU 浮点不保证各机器 bit-exact，可采用**单平台像素容差/感知差异指标**而不是伪造跨驱动哈希相同；
- 测试每个镜头至少 3 个时点 + 每个转场的连续帧 + 整片编码后的 1:1 对照与实际运动检查。

## 阶段 4：完整成片独立审片

- 一次从头到尾的真正观看与听感检查；不能拿 MP3/AAC 波形相似度充当已经听过。
- 关键高潮、各幕过渡、歌词与字幕、场景身份、角色动机、镜头节奏、突兀静止、亮度、眩光/闪烁都须按时间码记录。
- 若存在有明确依据的严重问题，回到局部试镜 / 工艺路线重新选择；**保留最初完整版本，改版不覆盖原文件**。
- 仅在创作负责人真诚认为作品达成艺术意图，并能从画面举证时，允许标记艺术 PASS；不因自动系统低估审美或人类曾提质疑就强制返工。

## 失效分类与持续学习

`TECH_FAIL` / `ART_REWORK` / `AUDIO_UNVERIFIED` / `RIGHTS_PENDING` / `READY_FOR_FULL_CUT` / `ACCEPTED_FIRST_CUT` 区分清楚。先积累**真实成功并被独立看过**的镜头/特效/角色组件，再择优固化为 Skill / 组件；不可把“用了 Three.js”本身当作已验证的 Skill。
