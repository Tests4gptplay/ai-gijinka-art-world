# 路线比较与选择规则

评分是**研究性先验判断，不是测得的质量评分**。需要实机试片才能改变“待验证”状态。1 = 对此项弱 / 5 = 研究预期较强；高成本为负项。AI 并非自动保证完成艺术审片。

| 路线 | 场景表现潜力 | 模型可编程性 | UI/文字 | 可控人物动画 | 可重复逐帧 | 制作门槛 / 风险 |
|---|---|---|---|---|---|---|
| A 浏览器混合 | 高（3D/Shader/DOM 结合） | 高 | **强** | 中：须分层/绑定素材 | 强，**需 GPU 实测** | 中；Remotion 许可证和 WebGL 后端 |
| B Motion Canvas / PixiJS | 高（精致动态平面 + 后期） | **高** | **强** | 中～高：有分层绘画与绑定时 | 强，需导出测试 | 低～中；复杂 3D 不擅长 |
| C Blender Eevee | **很高**（真实景深/灯光/材质） | 中：Python 可驱动，资产设计更难 | 中，最好外部合成 | 高：必须有角色建模/绑定 | 高，需锁定版本与随机 | **高**；需专业软件与资源 |
| D Godot Movie Maker | 高（动画系统+2D/3D） | 中～高 | 强 | 中～高：需资产/AnimationPlayer | 高，需物理导出测试 | 中；Movie Maker 输出需转码 |
| E ComfyUI 视频/图片 | 单镜头质感潜力高 | 中：JSON/工作流 API | 弱，文字另用矢量排版 | **不稳定**：身份/动作漂移 | 有种子仍有兼容性差异 | 高 GPU/模型/权利/时序风险 |

### 有限资源优先级

- **歌词排版、代码瀑布、屏幕 UI、窗口、控制台、图表**：先 B 或 A 的 HTML/CSS/Canvas，很多东西不需要 3D 网格。
- **故障空间、粒子场、流体/体积、机械镜头、物理材质**：A 的 WebGL2/GLSL/Three.js。若需要成熟资产/镜头编辑，C 更合适。
- **GPT 娘与其他 AI 娘同框、演出、表情**：先完成**角色身份可识别的原始/获许可分层素材**；用 B/D 或 C 控制表演，E 只辅助背景/某些镜头。
- **分支场景、编辑器游戏界面、剧情跳转或 POV 场景**：D 的场景树或 A 的 UI 布局。
- **歌曲全曲/用户要求精准音乐字幕**：使用全局帧时钟和统一 cue manifest；任何渲染器都必须从帧编号计算画面，不得凭 JS requestAnimationFrame 的实际墙钟时间积累误差。

### 技术审查不可替代审美判断

镜头数量、SDF/粒子数量、材质贴图分辨率、渲染耗时、帧总数、音画 PTS 正确都是**客观正确性**，并非视觉质量。独立审片的真实问题应是：**没有口头解释时，观众看得出设计意图吗？镜头、光色、空间、文字和动作真的在承载音乐情绪吗？** 详见 [QUALITY_GATE](QUALITY_GATE.md)。

### 实验验证后再排序

先在同一小段音频/自制节拍下制作 A、B 两条 8–12 秒动态样片。隐藏路线名的对照评审应记录实际片段、真实帧、时间码、优缺点及下一轮改动理由；C/D/E 只在表达需求明确时纳入。避免无根据地提前封死创作方法。
