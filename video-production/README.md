# 高品质 AI 辅助视频 / MV 制作方案库

> **文献方案 / 待做实机实验** · 调研时间：2026-10-18 · 独立公开研究，不是当前 CAH 的任务记录，也没有对本机安装、渲染或主观美学做出 PASS。
>
> 研究目标：为 AI 娘圈角色 PV、程序化 MV、B 站图文导览视频和日后由 CAH 协作完成的视频建立**可审查的高表现力制作路径**，避免再次把复杂叙事降格为暗背景上的几根细线、多边形的简单摆动。

## 核心观点

**固定艺术生产与质量验证的流程，不强制固定工具，更不能固定成「Python 2D 几何形状即最终美术」。** Three.js/WebGL2/GLSL 能做高级材质、空间与后期，但并不自动保证质量；浏览器 DOM/CSS 对 UI、编辑器、代码动态视觉往往更顺手；有角色表演时，分层角色资产与绑定动画可能比程序凭空画出人物稳定。生成式视频模型则可补充镜头素材，但连续性、控制和授权风险不应被忽略。

最终结果应可输出真正的视频文件、匹配时间轴与音频；视觉是否合格**必须经实际编码视频的动态审片**，而不是只凭原型说明、静态图、代码测试或原始 PNG。

## 防止重蹈此前的问题

1. **先验证“表现风格”再烧完整全曲。** 同一段自有/获许可音频或合成节拍上，做若干 8–12 秒有意义的多镜头样片，观看真实 MP4 而非文字设想或 4 张海报。
2. **禁止“视觉贫乏却技术全绿”的验收误判。** 低对比、长期近乎静止、缺少空间/版式层级、情绪变化无法感知：即使帧数和哈希正确也必须在美学门槛显式评议。
3. **至少一条路线能处理真实角色资产。** 本仓库的 [GPT 白龙娘图鉴](../CHARACTER_ATLAS.md) 只是**研究参考**；若制作新画面，应有权使用的分层人物资产，确保龙角、膜翼、鳞尾的身份连续性，不能简单拿银发通用少女冒充。
4. **脚本绘制和 GPU 技术是媒介，不是美术总监。** “用了 GLSL”或“13015 帧”本身不能证明影像感染力。需要对照审片决定表现力是否成立。
5. **有边界地选择工具。** 新大型专业软件安装、付费服务、账户接入遵循用户授权；不能把某一视频的作者声称实现等同于该软件在本机已验证可运行。

## 当前结论 / 下一步

**首选 A + B 实验**；当镜头需求明确涉及电影感空间、精致角色或物理光影时加 C；若需游戏 UI/交互世界加 D；AI 生图/生视频 E 只解决部分素材的高表现力，不承诺整片一致性。

**当前只有调研文档**：未克隆第三方代码、未添加工作流/依赖、未创建音视频、未调用商业生成 API、未改动 CAH。技术能力、授权和审美质量要在 [PILOT_SPEC.md](PILOT_SPEC.md) 下一阶段实测后才能写为“已验证”。
